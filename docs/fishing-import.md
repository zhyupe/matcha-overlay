# 外部时间区间导入协议（v1）

悬浮窗「地图事件 → 钓鱼」底部的「导入」按钮同时支持本格式和原有备份格式。其他系统只需输出 UTF-8 JSON 文件，不需要生成角色信息、抛竿事件或鱼获记录。

```json
{
  "format": "matcha-fishing-ranges",
  "version": 1,
  "ranges": [
    {
      "placeId": 425,
      "fishId": 4891,
      "baitId": 29717,
      "biteSeconds": [13.5, 19.2],
      "tug": 2
    },
    {
      "placeId": 425,
      "fishId": 4891,
      "baitId": 2585,
      "biteSeconds": [8, 45],
      "tug": 2
    }
  ]
}
```

示例时间和强度为演示数据，不代表实际鱼种的统计结论。

| 字段 | 规则 |
| --- | --- |
| `format` | 必须为 `matcha-fishing-ranges` |
| `version` | 必须为数字 `1` |
| `ranges` | 每条表示一个钓场 × 鱼 × 钓饵 × 状态组合；最多 10000 条 |
| `placeId` | 必填正整数，XIVAPI `PlaceName` 行 ID，即 `FishingSpot.PlaceName`，不是 `FishingSpot` 行 ID；海雾村为 425 |
| `fishId` | 必填正整数，鱼的 `Item` 行 ID |
| `baitId` | 必填正整数，有效钓饵的 `Item` 行 ID；以小钓大时填作为饵鱼的鱼的 Item ID |
| `biteSeconds` | 必填 `[最小秒数, 最大秒数]`，从抛竿到咬钩；允许小数、允许上下界相等，不含收杆动画；四舍五入到毫秒后必须是正的安全整数，且下界不大于上界 |
| `tug` | 可选：1 = 轻杆，2 = 中杆，3 = 重杆；未知则省略，不能填 0 或 null |
| `chum` | 可选布尔值，是否撒饵；省略为 false |
| `snagging` | 可选布尔值，是否启用钓组；省略为 false |
| `mooch` | 可选布尔值，是否以小钓大；省略为 false |

状态字段的缺省值表示明确关闭，不表示任意状态或未知状态。撒饵时的区间需单独提供，导入器不自动缩放时间。无法区分状态的数据应先在来源系统中整理。

只接受以上字段。ID 不接受名称或数字字符串；未知字段、null、无效上下界和文件内重复组合均拒绝，以免生成端字段拼写错误被忽略。无需 ID 已收录在前端当前目录中，但生成端须保证映射正确。单文件大小上限为 5 MB。

整份文件验证成功后才合并。组合键为 `placeId + fishId + baitId + chum + snagging + mooch`；已存在的同组合区间整条替换，未提供的组合和已有鱼获保留。重复导入不会增加副本。若新条目省略 tug，会移除同组合原先导入的 tug，前端仍可使用本地观测推断强度。空 ranges 不清空已有数据。

导入后，透明条使用该鱼在当前钓场所有钓饵及状态的区间包络；不透明条使用当前钓饵且状态完全匹配的区间。不同钓场的数据不混用。

底部「导出」保持原有完整备份格式（version、catches、profiles），其中 profiles 时间为毫秒。新格式只用于导入，不改变备份兼容性；备份可原样重新导入。
